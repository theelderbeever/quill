# Native type fixtures

Start the development services, then run from the repository root:

```sh
just seed-types
```

This explicitly replaces fixture data only. PostgreSQL's `type_coverage` schema
and ClickHouse's `quilt_test.type_coverage` table are dropped and recreated;
MySQL's `quilt_test.type_coverage` and Scylla's `type_coverage` tables are emptied.
The existing people dataset is unaffected. No generated data or LFS is needed.
The runner detects the mounted Scylla development TLS certificate.

Fixtures describe database types directly, independently of Quill or Arrow's
supported types. Each includes an integer `id` for projection checks:

```sql
-- PostgreSQL and Scylla
SELECT id FROM type_coverage.all_types;
-- MySQL and ClickHouse
SELECT id FROM quilt_test.type_coverage;
```

Compare these projections with individual type columns or `SELECT *`. A fixture
loading successfully does not establish that Quill can discover or project it;
these tables are intended to expose precisely those failures.

Coverage:

- PostgreSQL: numeric, text, binary, temporal, JSON/XML, network, geometric,
  text search, bit strings, UUID, LSN, xid8, all six built-in ranges and
  multiranges, arrays, enum, composite, and domain. One populated and one null row.
- MySQL: signed/unsigned integer widths, numeric, bit/boolean, temporal, string,
  binary, all text/blob sizes, enum, set, JSON, and all spatial families. One
  populated and one null row.
- Scylla: native scalar types, collections, tuple, frozen UDT and nested
  collection, plus a separate counter table (required by CQL). One populated
  and one null row in the main table.
- ClickHouse: integer widths through 256 bits, floats, decimal widths, strings,
  temporal types, UUID/IP, enums, collections, nullable/low-cardinality,
  geometry, JSON, Dynamic, Variant, and aggregate state types. Uses native
  defaults plus populated array and tuple values; column declarations in the SQL
  are the mapping for numbered `value_*` columns.

This covers concrete persisted type families, not every parameterization,
server extension, PostgreSQL internal/catalog type, or experimental type.
Aliases share a representation; recursive collection combinations are represented
by examples. ClickHouse Nothing and query-only Interval types are not standalone
stored columns. Add new stable server type families here as images evolve;
SQL errors intentionally fail the runner rather than silently omit coverage.
RustFS is object storage and has no database column types.

## RustFS datasets and federation

`just seed-types` also requires `uv` and runs `objects.py` with isolated Python
dependencies. It creates the `quill` bucket and overwrites only
`people_csv/people.csv`, `people_json/people.json`, and
`people_parquet/people.parquet`. All three contain the same three rows with
`id`, `name`, `city`, and `logins` columns. JSON uses newline-delimited objects.
Uploads are read back and compared with the generated bytes. The runner detects
RustFS TLS; direct invocation defaults to HTTPS with the development CA, or accepts
`RUSTFS_ENDPOINT=http://localhost:9000` for plaintext services.

The repository `.quill.toml` registers these as `people_csv`, `people_json`, and
`people_parquet` in the `files` connection. Open its `federation` workspace to
connect PostgreSQL (`pg`), MySQL (`mysql`), ClickHouse (`ch`), Scylla (`scylla`),
and RustFS (`files`) together. This configuration targets the TLS Docker setup;
start with `just docker --tls` before seeding. SQLite remains an independent
in-memory connection because Compose does not run SQLite.
